## 1. C++ 模板 (Templates) 與類別繼承架構

### 1.1 函式模板與類別模板
為了實現通用資料結構，C++ 提供模板機制避免對不同資料型態重複編寫邏輯：

```cpp
template <class T>
void SelectionSort(T *a, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min_idx = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[min_idx]) min_idx = j;
        }
        T temp = a[i]; a[i] = a[min_idx]; a[min_idx] = temp;
    }
}
```

### 1.2 繼承與虛擬函式 (Subtyping and Inheritance)
溫敏淦老師 PPT 以 `Bag` 與 `Stack` 為例說明物件導向繼承架構：
- `Bag`：無特定順序的物件容器集合。
- `Stack`：繼承自 `Bag`，但強制實施 **後進先出 (LIFO)** 的取出規則。
- **虛擬函式 (Virtual Function)**：在基底類別中標記 `virtual`，支援執行時期多型 (Dynamic Polymorphism)。

```cpp
class Bag {
protected:
    int *array;
    int capacity;
    int top;
public:
    Bag(int max_size = 10);
    virtual ~Bag();
    virtual void Push(const int val);
    virtual int* Pop();
    virtual bool IsEmpty() const;
};

class Stack : public Bag {
public:
    Stack(int max_size = 10) : Bag(max_size) {}
    // 重寫 Pop 函式，嚴格遵從 LIFO
    int* Pop() override {
        if (IsEmpty()) return 0;
        return &array[top--];
    }
};
```

## 2. 堆疊 (Stack) 概念與系統堆疊 (System Stack)

### 2.1 堆疊特性與 ADT 3.1
- **特性**：後進先出 (LIFO, Last-In First-Out)。插入與刪除皆在同一個端點——**頂端 (Top)** 進行。
- 堆疊物件：$S = (a_0, a_1, \dots, a_{n-1})$，其中 $a_0$ 為底端 (Bottom)，$a_{n-1}$ 為頂端 (Top)。

### 2.2 系統堆疊與活化記錄 (Activation Record / Stack Frame)
當程式呼叫函式時，作業系統會在系統堆疊 (System Stack) 自動配置一個活化記錄：
- **返回位址 (Return Address)**：被呼叫函式結束後，CPU 應接續執行的指令位址。
- **傳遞引數 (Arguments)** 與 **局部變數 (Local Variables)**。
- 函式執行完畢，其 Activation Record 被 Pop 釋放，控制權交還給呼叫者。

## 3. 佇列 (Queue) 與環狀佇列 (Circular Queue)

### 3.1 佇列特性與線性佇列之缺陷
- **特性**：先進先出 (FIFO, First-In First-Out)。在 **後端 (Rear)** 插入元素，在 **前端 (Front)** 刪除元素。
- **線性佇列的「假溢位 (False Overflow)」**：
  - 隨著頻繁的 Push 與 Pop，`front` 與 `rear` 持續向高位址移動。
  - 當 `rear == capacity - 1` 時，即使陣列前端已有大量空間被 Pop 清空，依然無法再插入元素！
  - 若每次 Pop 都將所有元素往前搬移一格，時間代價高達 $O(n)$。

---

### 3.2 環狀佇列 (Circular Queue) 解決方案
將陣列邏輯上看成首尾相連的環狀結構，索引透過模數運算前進：
$$next\_pos = (pos + 1) \bmod \text{capacity}$$

```text
指標初始約定：
front 與 rear 初始值均設為 0
插入元素：rear = (rear + 1) % capacity; queue[rear] = item;
刪除元素：front = (front + 1) % capacity; item = queue[front];
```

#### 環狀佇列如何判斷「空佇列」與「滿佇列」？
當 `front == rear` 時，可能是**全空**，也可能是**全滿**。課堂提供兩大解決策略：

1. **策略 A：留一空格法 (One Empty Slot - 教材標準做法)**
   - 容量為 $N$ 的陣列最多只容納 $N-1$ 個元素。
   - **空佇列條件**：`front == rear`
   - **滿佇列條件**：`(rear + 1) % capacity == front`
2. **策略 B：旗標變數法 (Tag / Counter Flag)**
   - 陣列可完整裝入 $N$ 個元素。
   - 增加布林變數 `tag`（最後一次操作是 Push 則 `tag = 1`；是 Pop 則 `tag = 0`）。
   - `front == rear && tag == 0` $\implies$ 空；`front == rear && tag == 1` $\implies$ 滿。

```cpp
template <class T>
class CircularQueue {
private:
    T *queue;
    int front, rear, capacity;
public:
    CircularQueue(int queueCapacity = 10) : capacity(queueCapacity) {
        queue = new T[capacity];
        front = rear = 0;
    }
    bool IsEmpty() const { return front == rear; }
    bool IsFull() const { return (rear + 1) % capacity == front; }
    void Push(const T& x) {
        if (IsFull()) throw "Queue is full!";
        rear = (rear + 1) % capacity;
        queue[rear] = x;
    }
    void Pop() {
        if (IsEmpty()) throw "Queue is empty!";
        front = (front + 1) % capacity;
    }
    T& Front() const {
        if (IsEmpty()) throw "Queue is empty!";
        return queue[(front + 1) % capacity];
    }
};
```

## 4. 經典應用：老鼠走迷宮問題 (The Maze Problem)

### 4.1 資料結構設計
- **迷宮陣列**：`maze[m+2][p+2]`，外圍一圈設定為 `1`（障礙牆壁），避免走訪邊界溢位檢查。
- **標記陣列**：`mark[m+2][p+2]`，初始全為 0。走過的格子設為 1，防止無窮繞圈。
- **8 個移動方向與偏移量結構 (Offsets)**：
  ```cpp
  struct Offsets {
      int a, b; // a: 列偏移 (row), b: 行偏移 (col)
  };

  // 8 個方位：N, NE, E, SE, S, SW, W, NW
  Offsets move_dir[8] = {
      {-1,  0}, // 0: N
      {-1,  1}, // 1: NE
      { 0,  1}, // 2: E
      { 1,  1}, // 3: SE
      { 1,  0}, // 4: S
      { 1, -1}, // 5: SW
      { 0, -1}, // 6: W
      {-1, -1}  // 7: NW
  };
  ```
- **堆疊元素結構**：
  ```cpp
  struct Element {
      int row; // 當前列
      int col; // 當前行
      int dir; // 下一步欲嘗試的方向 (0~7)
  };
  ```

### 4.2 回溯演算法 (Backtracking Algorithm)

```cpp
void Path(const int m, const int p) {
    mark[1][1] = 1; // 起點
    Stack<Element> stack(m * p);
    Element position = {1, 1, 2}; // 預設先朝東方 (dir=2) 探索
    stack.Push(position);

    while (!stack.IsEmpty()) {
        position = *stack.Pop();
        int r = position.row;
        int c = position.col;
        int d = position.dir;

        while (d < 8) {
            int nextRow = r + move_dir[d].a;
            int nextCol = c + move_dir[d].b;

            if (nextRow == m && nextCol == p) { // 到達終點 Exit!
                cout << "Success! Path found." << endl;
                return;
            }

            if (maze[nextRow][nextCol] == 0 && mark[nextRow][nextCol] == 0) {
                // 可前進：儲存當前點及下個欲嘗試方向
                position.row = r; position.col = c; position.dir = d + 1;
                stack.Push(position);
                r = nextRow; c = nextCol; d = 0;
                mark[r][c] = 1; // 標記已拜訪
            } else {
                d++; // 嘗試下一個方位
            }
        }
        // 8 個方位皆走不通，回溯 (Backtrack) 至堆疊頂端節點
    }
    cout << "No path found in maze!" << endl;
}
```

## 5. 運算式求值與轉換 (Expressions)

### 5.1 運算式三種標註法
1. **中序式 (Infix)**：`A + B`（符合人類閱讀習慣，但計算需依賴括號與優先權）。
2. **後序式 (Postfix / 逆波蘭式)**：`A B +`（電腦編譯器首選，無括號，由左至右單趟求解）。
3. **前序式 (Prefix)**：`+ A B`。

---

### 5.2 後序式求值演算法 (Evaluation of Postfix)
使用堆疊進行求值，時間複雜度 $O(n)$：
1. 由左至右掃描 Token。
2. 若 Token 是**運算元 (Operand)** $\implies$ Push 進堆疊。
3. 若 Token 是**運算子 (Operator)** $\implies$ Pop 出頂端兩個運算元（先出者為右運算元 `op2`，後出者為左運算元 `op1`），計算 `op1 (op) op2`，將結果 Push 回堆疊。
4. 最終留在堆疊中的唯一元素即為算式解答。

#### 實例計算：`6 2 / 3 - 4 2 * +`
| 掃描 Token | 動作 | 堆疊內容 (Bottom $\to$ Top) | 說明 |
| :---: | :--- | :--- | :--- |
| `6` | Push | `6` | 運算元入棧 |
| `2` | Push | `6, 2` | 運算元入棧 |
| `/` | Pop 2, 6 | `3` | $6 / 2 = 3$ 入棧 |
| `3` | Push | `3, 3` | 運算元入棧 |
| `-` | Pop 3, 3 | `0` | $3 - 3 = 0$ 入棧 |
| `4` | Push | `0, 4` | 運算元入棧 |
| `2` | Push | `0, 4, 2` | 運算元入棧 |
| `*` | Pop 2, 4 | `0, 8` | $4 \times 2 = 8$ 入棧 |
| `+` | Pop 8, 0 | `8` | $0 + 8 = 8$ 入棧 |
| **結果** | 最終輸出 | **8** | 計算完成 |

---

### 5.3 中序轉後序演算法 (Infix to Postfix)

> [!IMPORTANT]
> **雙優先權設計**：
> 運算子在堆疊內外必須擁有不同優先權！尤其是左括號 `(`：
> - 在堆疊外時優先權極高（必須無條件入棧）。
> - 進入堆疊後優先權降至最低（保證任何後續運算子都能壓在它上面，直到遇到右括號 `)` 才能將它彈出）。

#### 運算子優先權對照表 (溫敏淦老師 PPT 數值規範)：
| 運算子 | 符號 Token | 堆疊內優先權 (In-Stack Priority, `isp`) | 堆疊外優先權 (In-Coming Priority, `icp`) |
| :--- | :---: | :---: | :---: |
| 右括號 | `)` | - | - |
| 乘、除、取模 | `*`, `/`, `%` | **12** | **12** |
| 加、減 | `+`, `-` | **13** | **13** |
| 左括號 | `(` | **0** (最低，不被擠出) | **20** (最高，無條件入棧) |
| 算式結束標記 | `#` / `eos` | **19** | **19** |

*(註：優先權數值越小，代表優先運算權限越高；在程式中以小於等於進行比較)*

#### 轉換規則演算法：
1. 從左至右逐一讀取 Token。
2. 若 Token 為**運算元** $\implies$ **直接輸出**至後序式。
3. 若 Token 為**右括號 `)`** $\implies$ 不斷從堆疊 Pop 並輸出運算子，直到遇見左括號 `(`，最後將 `(` 丟棄。
4. 若 Token 為其他運算子 $\implies$ 當 `isp[stack.Top()] <= icp[token]` 時，不斷將堆疊頂端 Pop 並輸出；直到頂端優先權低於當前 token，再將該 token Push 入堆疊。

#### 手算範例：將 `a / b - c + d * e - a * c` 轉後序式
- **括號法驗證**：
  1. 完整加括號：`((((a / b) - c) + (d * e)) - (a * c))`
  2. 將運算子移至右括號外：`((((a b /) c -) (d e *) +) (a c *) -)`
  3. 拔除括號：`a b / c - d e * + a c * -`
