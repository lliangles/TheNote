## 1. 平衡二元搜尋樹 (AVL Tree - Adelson-Velsky & Landis)

一般的 BST 在最壞情況下會退化為單向鏈結串列 ($O(n)$)。AVL 樹是歷史上第一種**自我平衡二元搜尋樹**：
- **平衡因子 (Balance Factor, BF)**：
  $$BF(T) = h_L - h_R$$
  其中 $h_L, h_R$ 分別為左子樹與右子樹的高度。
- **AVL 樹條件**：所有節點的平衡因子必須落在 **$\{-1, 0, 1\}$** 之間。

### 1.1 四種旋轉平衡機制 (Rotations - 必考)
當插入新節點破壞平衡 ($|BF| > 1$) 時，針對「距離插入點最近之失衡祖先節點 $A$」進行旋轉：

| 失衡型態 | 成因 | 解決旋轉操作 |
| :--- | :--- | :--- |
| **LL 型** | 新節點插入在 $A$ 的**左子節點之左子樹** | **單右旋 (Single Right Rotation)** |
| **RR 型** | 新節點插入在 $A$ 的**右子節點之右子樹** | **單左旋 (Single Left Rotation)** |
| **LR 型** | 新節點插入在 $A$ 的**左子節點之右子樹** | **雙旋轉 (先對左子進行左旋，再對 $A$ 進行右旋)** |
| **RL 型** | 新節點插入在 $A$ 的**右子節點之左子樹** | **雙旋轉 (先對右子進行右旋，再對 $A$ 進行左旋)** |

- 搜尋、插入、刪除時間複雜度嚴格保證為：$$\mathbf{O(\log n)}$$

## 2. 紅黑樹 (Red-Black Tree)

紅黑樹透過給節點著色（紅色或黑色），在插入/刪除時放寬嚴格高度限制，減少旋轉頻率：
1. 每個節點不是**紅色**就是**黑色**。
2. **根節點必為黑色**。
3. 所有葉節點 (NIL 哨兵節點) 皆為黑色。
4. **不允許連續紅節點**（若一個節點為紅色，其兩子節點必為黑色）。
5. 從任一節點到其所有後代葉節點的簡單路徑上，均包含**相同數量的黑色節點 (Black Height)**。

---

## 3. 多向搜尋樹與 B 樹 (B-Trees)

當資料量龐大、必須存放在磁碟時，過高的樹高會造成昂貴的磁碟 I/O。B 樹將二元推廣至 $m$ 元：
- **$m$ 階 B-Tree 性質**：
  1. 根節點至少擁有 2 個子節點（除非只有 1 個節點）。
  2. 除根節點外，所有內部節點至少擁有 $\lceil m/2 \rceil$ 個子節點，最多擁有 $m$ 個子節點。
  3. 所有葉節點皆位於**完全相同的階層**。
  4. 節點分裂 (Split) 與合併 (Merge) 機制維持絕對平衡。
- **B+ Tree 演進**：資料全部集中在葉節點，且葉節點以雙向串列相連，支援極高效率的**範圍查詢 (Range Query)**，成為 MySQL InnoDB 資料庫核心索引架構。
