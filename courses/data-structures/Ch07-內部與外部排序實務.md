## 1. 排序基礎概念與穩定性 (Sorting Fundamentals & Stability)

- **內部排序 (Internal Sort)**：待排序資料量可完全容納於電腦主記憶體中進行排序。
- **外部排序 (External Sort)**：資料量過大，無法一次放入記憶體，需頻繁與外存 (硬碟/磁帶) 交換。
- **穩定排序 (Stable Sort)**：若序列中有鍵值相同的紀錄 $R_i, R_j$ 且原始順序 $R_i$ 在 $R_j$ 之前，排序後 $R_i$ 依然維持在 $R_j$ 之前。

| 排序法 | 穩定性 (Stability) | 額外空間複雜度 | 備註 |
| :--- | :---: | :---: | :--- |
| **插入排序 (Insertion Sort)** | **穩定 (Stable)** | $O(1)$ | 資料大部分有序時極快 |
| **快速排序 (Quick Sort)** | **不穩定 (Unstable)** | $O(\log n)$ | 平均時間常數最小，實務最快 |
| **合併排序 (Merge Sort)** | **穩定 (Stable)** | $O(n)$ | 時間恆為 $O(n \log n)$ |
| **堆積排序 (Heap Sort)** | **不穩定 (Unstable)** | $O(1)$ | 原地排序，最壞情況也是 $O(n \log n)$ |
| **基數排序 (Radix Sort)** | **穩定 (Stable)** | $O(r)$ | 非比較型排序 |

## 2. 插入排序法 (Insertion Sort)

### 2.1 演算法原理
將元素逐一插入已排序好的前方子序列中，從後向前比對並後移較大元素：

```cpp
template <class T>
void InsertionSort(T *a, const int n) {
    for (int j = 1; j < n; j++) {
        T temp = a[j];
        int i = j - 1;
        while (i >= 0 && a[i] > temp) {
            a[i + 1] = a[i]; // 較大者後移
            i--;
        }
        a[i + 1] = temp; // 插入適當位置
    }
}
```

### 2.2 LOO 逆序數與效能分析
- **LOO (Left Out of Order)**：若一個元素小於其前面的某個元素，即構成逆序。
- **定理**：若長度為 $n$ 的序列中恰有 $k$ 個逆序對 (Inversions)，則插入排序耗時為：
  $$T(n) = O(n + k)$$
  - **最佳情況 (Best Case)**：序列已排序 ($k=0$) $\implies O(n)$。
  - **最壞情況 (Worst Case)**：序列完全反序 ($k = n(n-1)/2$) $\implies O(n^2)$。

## 3. 快速排序法 (Quick Sort - C.A.R. Hoare)

### 3.1 分割演算法 (Partitioning)
挑選一元素為樞紐 (Pivot)，將小於 Pivot 的元素放左側，大於 Pivot 的元素放右側：

```cpp
template <class T>
void QuickSort(T *a, const int left, const int right) {
    if (left < right) {
        int i = left, j = right + 1;
        T pivot = a[left]; // 取最左元素為 pivot
        do {
            do i++; while (a[i] < pivot);
            do j--; while (a[j] > pivot);
            if (i < j) swap(a[i], a[j]);
        } while (i < j);
        swap(a[left], a[j]); // 將 pivot 歸位至 j

        QuickSort(a, left, j - 1);  // 遞迴左半部
        QuickSort(a, j + 1, right); // 遞迴右半部
    }
}
```

### 3.2 避免最差情況：三數中值法 (Median-of-three)
- 若每次 Pivot 皆選到極端值（如已排序陣列選最左邊），遞迴深度高達 $n$，退化為 $O(n^2)$！
- **改進**：取最左、最右與中間三數的**中位數 (Median)** 作為 Pivot，使分割更趨對稱。
- **時間複雜度**：平均 $O(n \log n)$，最壞 $O(n^2)$。
- **堆疊空間複雜度**：平均 $O(\log n)$，最壞 $O(n)$。

## 4. 比較式排序之理論下限：決策樹 (Decision Tree Bound)

> [!IMPORTANT]
> **溫敏淦老師 PPT 重點證明題**：證明任何以比較為基礎的排序演算法，其最壞情況時間複雜度下限必為 **$\Omega(n \log n)$**。

### 證明過程：
1. 長度為 $n$ 的相異元素序列，其可能的全排列共有 **$n!$** 種。
2. 任何比較式演算法皆可對應為一棵二元決策樹 (Binary Decision Tree)，每個內部節點代表一次元素比較 ($a_i \le a_j$)，每個葉節點代表一種可能的排序結果。
3. 為了涵蓋所有 $n!$ 種排列，決策樹的葉節點數量 $L$ 必須滿足：
   $$L \ge n!$$
4. 深度（高度）為 $h$ 的二元樹最多擁有 $2^{h-1}$ 個葉節點，因此：
   $$2^{h-1} \ge L \ge n! \implies h - 1 \ge \log_2(n!)$$
   $$h \ge \lceil \log_2(n!) \rceil + 1$$
5. 根據史特靈公式 (Stirling's Approximation) 或積分近似：
   $$\log_2(n!) = \sum_{i=1}^n \log_2(i) \ge \int_1^n \log_2(x) \, dx = \Omega(n \log n)$$
   故比較式排序的最壞情況比較次數**必定至少為 $\Omega(n \log n)$**！ $\blacksquare$

## 5. 合併排序法 (Merge Sort)

### 5.1 疊代版 vs 遞迴版
- **疊代版 (Iterative)**：從步長 $s = 1$ 開始，相鄰兩兩合併成大小為 2 的序列；接著 $s = 2$ 合併為大小為 4 的序列，共需 $\lceil \log_2 n \rceil$ 個 Passes。
- **遞迴版 (Divide & Conquer)**：二分切割至長度為 1，回溯時執行 `Merge`。
- **時間複雜度**：最佳、平均、最壞皆為 **$O(n \log n)$**。
- **空間複雜度**：需要大小為 $n$ 的輔助陣列 $\implies O(n)$。

---

## 6. 堆積排序法 (Heap Sort)

堆積排序為原地排序 (In-place)，不需額外陣列空間 ($O(1)$ 輔助空間)。

### 6.1 階段一：$O(n)$ 建立 Max Heap (線性建堆證明)
將陣列直接轉為 Max Heap 時，從最後一個非葉節點 $i = \lfloor n/2 \rfloor$ 開始倒序往前執行 `adjust` (Percolate Down)：

#### 線性時間證明：
深度為 $h$ 的完全二元樹，第 $i$ 層最多有 $2^{i-1}$ 個節點，各節點最多向下調整 $h - i$ 層：
$$\text{Total Time} = \sum_{i=1}^h 2^{i-1} \cdot (h - i) = O(n)$$
*(比逐一 Push 的 $O(n \log n)$ 快很多！)*

### 6.2 階段二：排序循環 ($O(n \log n)$)
重複 $n-1$ 次：將根節點 (最大值) 與當前堆積最後一個元素對調，然後對根節點執行 `adjust`。
- **總時間複雜度**：$$O(n) + O(n \log n) = \mathbf{O(n \log n)}$$

## 7. 基數排序法 (Radix Sort)

基於鍵值多個維度進行排序的**非比較型演算法**：
- **LSD (Least Significant Digit)**：由最低位數（個位 $\to$ 十位 $\to$ 百位）優先排序。
- 每個桶子 (Bucket) 以鏈結串列實現，每輪分配 (Distribution) 入對應的桶子，再依序收集 (Collection)。
- **時間複雜度**：$$O(d(n + r))$$
  - $d$：鍵值位數 (Digits)。
  - $r$：基數 (Radix，例如十進制 $r = 10$)。
  - $n$：資料總筆數。

## 8. 內部排序演算法全方位大對決

| 演算法 | 最佳時間 (Best) | 平均時間 (Average) | 最差時間 (Worst) | 空間複雜度 | 穩定性 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **選擇排序** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不穩定 |
| **插入排序** | $\mathbf{O(n)}$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | **穩定** |
| **快速排序** | $O(n \log n)$ | $\mathbf{O(n \log n)}$ | $O(n^2)$ | $O(\log n)$ | 不穩定 |
| **合併排序** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | **穩定** |
| **堆積排序** | $O(n \log n)$ | $O(n \log n)$ | $\mathbf{O(n \log n)}$ | $\mathbf{O(1)}$ | 不穩定 |
| **基數排序** | $O(d(n+r))$ | $O(d(n+r))$ | $O(d(n+r))$ | $O(r)$ | **穩定** |

## 9. 外部排序 (External Sorting)

當資料量遠超過記憶體時（例如 750 筆記憶體容量要排序 4500 筆資料）：

1. **初始回合產生 (Runs Generation)**：
   - 每次讀入 750 筆至記憶體，以內部排序 (如 QuickSort) 排好後寫出至外存，共產生 6 個 Runs。
2. **$k$ 路合併 ($k$-Way Merging)**：
   - 使用 **輸者樹 (Loser Tree)** 輔助挑選 $k$ 個 Runs 的當前最小值。
3. **雙重緩衝處理 (Double Buffering)**：
   - 設定多個輸入緩衝區與兩個輸出緩衝區，使得 **CPU 合併運算** 與 **磁碟 I/O 讀寫** 能平行重疊 (Overlap) 執行。
4. **霍夫曼樹 (Huffman Tree) 最佳化合併順序**：
   - 若各 Run 長度不一，合併不同 Run 的代價不同。以各 Run 長度作為權重建立霍夫曼樹，使其**加權外部路徑長度最小化**，達成最少 I/O 傳輸量！
