# Ch02 關聯式資料模型與完整性限制 (Relational Data Model & Integrity Constraints)

> [!NOTE] 課程資訊與學習目標
> - **授課進度**：第 2~3 週課程
> - **核心目標**：理解傳統三大資料模型演進、精通關聯式資料庫重要術語與數學定義、掌握候選鍵/主鍵/外鍵之約束機制、透徹理解實體與參照完整性限制、理解交易 ACID 特性。

---

## 1. 傳統三大資料模型比較 (Data Models Comparison)

| 資料模型 | 結構特性 | 優點 | 缺點 |
|:---|:---|:---|:---|
| **階層式 (Hierarchical)** | 樹狀結構（Tree），單一父節點，一對多關係 | 結構直覺、查詢路徑固定時效能極佳 | **無法直接表達多對多關係**、結構變更困難 |
| **網路式 (Network)** | 網狀圖形結構（Graph），可有多個父節點 | 支援多對多關係、存取靈活度高 | 指標關聯極度複雜、程式設計與維護成本巨大 |
| **關聯式 (Relational)** | **二維表格結構（Table）**，以數值鍵值建立關聯 | **概念最直覺**、支援強大 SQL 語言、具高資料獨立性 | 大量資料多表關聯（JOIN）時需消耗較多運算資源 |

---

## 2. 關聯式資料模型核心術語對照

關聯式模型奠基於數學的集合論（Set Theory）：

| 關聯式數學術語 | 實體資料庫術語 | 常用白話解說 |
|:---|:---|:---|
| **Relation（關聯）** | Table（資料表） | 一個二維資料表格 |
| **Tuple（元組）** | Row / Record（記錄列） | 表格中的橫列，代表單一實體資料 |
| **Attribute（屬性）** | Column / Field（欄位） | 表格中的直欄，代表某種資料特徵 |
| **Domain（值域）** | Data Type + Range | 該屬性合法取值的範圍與型態 |
| **Relation Schema** | Table Definition | 資料表的結構綱要描述，如 $R(A_1, A_2, \dots, A_n)$ |
| **Degree（度數）** | Number of Columns | 該關聯中屬性（欄位）的總數量 |
| **Cardinality（基數）** | Number of Rows | 該關聯中當前元組（資料列）的總筆數 |

## 3. 鍵值體系完全解析 (Keys in Relational Model)

> [!IMPORTANT] 各種鍵（Key）的層次與定義
> 1. **Super Key（超鍵）**：
>    - 能在關聯中**唯一識別**每一筆 Tuple 的屬性集合。
>    - 只要包含候選鍵的集合皆為超鍵（可包含多餘的贅餘屬性）。
> 2. **Candidate Key（候選鍵）**：
>    - **最小超鍵（Minimal Super Key）**。
>    - 具備唯一性，且去除任一屬性後即失去唯一識別能力（無贅餘屬性）。
> 3. **Primary Key（主鍵, PK）**：
>    - 從候選鍵中挑選出來，作為該資料表代表性唯一識別之屬性。
> 4. **Foreign Key（外鍵, FK）**：
>    - 一個資料表中的欄位集合，其取值**參照（Reference）至另一個資料表的主鍵**，用以建立表格間的關聯性。

```
超鍵 (Super Keys)
  └── 候選鍵 (Candidate Keys，最小超鍵)
        ├── 主鍵 (Primary Key，選定之代表)
        └── 替代鍵 (Alternate Keys，未選為 PK 的其他候選鍵)
```

## 4. 關聯式資料庫完整性限制 (Integrity Constraints)

為確保資料庫內數據的正確性、真實性與一致性，DBMS 強制實施三大完整性限制：

### (1) 實體完整性 (Entity Integrity)
- **規定**：**主鍵（Primary Key）中的任何屬性值，絕對不能為 `NULL`（空值）！**
- **理由**：主鍵是用來唯一標識每筆記錄的基石；若主鍵為 NULL，將無法辨別該筆實體是否存在。

### (2) 參照完整性 (Referential Integrity)
- **規定**：外鍵（Foreign Key）的值只有兩種可能：
  1. 必須等於所參照表格之主鍵的某個有效值。
  2. 或者為 `NULL`（若業務邏輯允許外鍵為空）。
- **理由**：防止出現「孤兒記錄（Orphan Records）」，確保表格間的關聯關係合法。

### (3) 值域完整性 (Domain Integrity)
- 欄位輸入值必須符合定義的值域範圍與資料型態（例如：年齡必須是 $\ge 0$ 的整數）。

## 5. 交易特性 ACID (Transaction Properties)

資料庫交易（Transaction）是一系列邏輯操作單元，必須完全滿足 ACID 特性：

- **Atomicity（原子性）**：「All or Nothing」，交易中的所有指令要麼全部成功執行，要麼完全不執行（發生錯誤立即 Rollback 回滾）。
- **Consistency（一致性）**：交易執行前後，資料庫必須維持合法的完整性狀態。
- **Isolation（隔離性）**：多個交易同時並行執行時，彼此互不干擾，執行結果與依序循序執行一致。
- **Durability（持續性 / 耐久性）**：一旦交易 Commit 提交成功，其產生的變更將永久保存在儲存媒體中，即使系統當機亦不遺失。

> [!EXAMPLE] 經典轉帳實例
> A 帳戶轉帳 1000 元給 B 帳戶：
> 1. `A 帳戶餘額 - 1000`
> 2. `B 帳戶餘額 + 1000`
> 兩者必須綁定在同一個交易中滿足原子性，不可發生「A 扣了錢但 B 沒收到」的狀態！
