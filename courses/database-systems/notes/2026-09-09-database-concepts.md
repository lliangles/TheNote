####  資料模型(ImplementationData Model)
	 階層式(Hierarchical)
	 網路式(Network)
	 關聯式(Relational)
	

資料儲存模式

| 資料模型               | 優點                                                  | 缺點                                    |
| ------------------ | --------------------------------------------------- | ------------------------------------- |
| 階層式 (Hierarchical) | * 樹狀結構簡單明瞭  <br>* 查詢效能佳（透過固定路徑）                     | * 無法直接處理多對多關係  <br>* 修改資料結構非常困難       |
| 網路式 (Network)      | * 可多父節點*<br>* 存取靈活度較階層式高                            | * 結構過於複雜  <br>* 程式設計與維護成本高            |
| 關聯式 (Relational)   | * 結構直覺（二維表格）  <br>* 使用 SQL 語言<br>* 資料獨立性高，更改結構不影響程式 | * 大量資料關聯（Join）時效能較差  <br>* 較難應對非結構化資料 |

[[關聯式資料庫]]（RDBMS）的核心運作原理可以拆解為以下三個關鍵要素：

- 二維表格結構（Table）：  
    將現實世界的資料抽象化為資料表。每張表由「行（Column，代表欄位/屬性）」與「列（Row，代表資料記錄）」組成。
- 鍵值與關聯（Keys & Relationships）：  
    透過主鍵（Primary Key）確保每筆記錄的唯一性
    利用外鍵（Foreign Key）將不同資料表建立起「一對多」或「多對多」的連結，避免資料重複儲存
- ACID 交易機制（Transactions）：  
    為了確保數據的正確與安全，執行任何資料更動時必須完全符合 
    Atomicity（原子性）
    Consistency（一致性）
    Isolation（隔離性）
    Durability（持續性）
